# CGIAR Climate Action — S2S Technical Platform

Technical knowledge and access portal for the IWMI-led CGIAR Climate Action work
on seasonal-to-subseasonal (S2S) forecasting.

Built with **Jekyll**, which GitHub Pages runs natively. There is no build
pipeline to maintain, no npm, no CI configuration and no local setup required to
edit content — researchers change a markdown file in the GitHub web editor and
the site republishes itself.

> **Setting it up for the first time?** Follow
> [`SETUP-GITHUB-PAGES.md`](SETUP-GITHUB-PAGES.md) — step by step, browser only.
>
> **Editing content?** You want [`EDITING-GUIDE.md`](EDITING-GUIDE.md), not this
> file. This one is for whoever sets the repository up and looks after the
> templates.

## Publishing it

Full instructions for this repository are in
[`SETUP-GITHUB-PAGES.md`](SETUP-GITHUB-PAGES.md). The short version:

1. Push the contents of this folder to a GitHub repository, at the repository
   **root**.
2. **Settings → Pages** → Source: *Deploy from a branch*, branch `main`, folder
   `/ (root)`.
3. Set `baseurl` and `url` in `_config.yml` to match the address GitHub gives you:

   | Your site address | `baseurl` | `url` |
   | --- | --- | --- |
   | `https://wrd-iwmi.github.io/s2s-platform/` | `"/s2s-platform"` | `"https://wrd-iwmi.github.io"` |
   | `https://wrd-iwmi.github.io/` | `""` | `"https://wrd-iwmi.github.io"` |
   | `https://s2s.iwmi.org/` | `""` | `"https://s2s.iwmi.org"` |

   These are **already set** for `wrd-iwmi/s2s-platform`.

That is the whole deployment. Every push to `main` republishes.

**Do not add a `.nojekyll` file** — it switches off the build that makes this
site work.

## Optional: previewing locally

Not needed to publish, and not needed to edit. Useful if you are changing
layouts.

```bash
bundle install
bundle exec jekyll serve
# http://localhost:4000/s2s-platform/
```

Requires Ruby 3.x. The `Gemfile` pins `github-pages`, which installs the exact
Jekyll version GitHub runs, so what you see locally is what gets published.

## Design decisions worth preserving

- **No plugins.** `plugins: []` in `_config.yml`. The sitemap, robots.txt and SEO
  tags are generated by the site's own templates. Nothing can break because a
  plugin changed or was dropped from the GitHub Pages allowlist.
- **No web fonts.** The type stack resolves to good system faces everywhere.
  That removes 100–300&nbsp;KB and a render-blocking request, which matters on
  the mobile connections much of the audience uses.
- **Inline SVG diagrams, not images.** They scale, they theme, they are
  searchable and they cost a few KB.
- **Progressive enhancement.** Filters, the three-level method tabs and the
  mobile menu are enhancements. With JavaScript off, every page still shows all
  of its content.
- **Colour is never the only signal.** Status is always carried by its text
  label as well as its colour.
- **One CSS file, tokens at the top.** Change a custom property in
  `assets/css/style.css` and the whole site follows.

If you extend the site, please keep: semantic HTML, visible focus states, a text
alternative for every diagram, tables wrapped in `.table-scroll`, and WCAG 2.2 AA
contrast.

## The three ways content arrives

| Route | Who it suits | How |
| --- | --- | --- |
| **Edit markdown on GitHub** | Anyone, once shown | `EDITING-GUIDE.md`. Fastest, no person in the loop. |
| **Jupyter notebook** | Anything computational | Researcher sends `.ipynb`; run `_scripts/notebook_to_page.py`. See `notebooks/README.md`. |
| **Word intake form** | People who will not leave Word | Researcher fills a form from `intake-forms/`; run `_scripts/docx_to_page.py`. See `intake-forms/README.md`. |

Both converters are plain Python 3 with no dependencies — a `.ipynb` is JSON and
a `.docx` is a zip of XML, and both are read with the standard library. They run
on your machine, not on GitHub, so there is no CI to maintain and no way for a
bad submission to break the live site.

**Always read what a converter produced before committing it.** They are
faithful, but they cannot tell whether the content is correct.

## The map

`_data/geography.yml` drives the homepage map — three sections:

- **`settings`** — height (`340` desktop / `260` mobile), starting view, and
  `fit_to_data` to zoom automatically around everything on the map.
- **`countries`** — the pin markers. Name, lat, lon, note, optional link.
- **`layers`** — optional GeoJSON files from `assets/geo/`. Points, lines or
  polygons, each with its own colour, fill opacity, line weight and popup
  fields. A layer switcher appears automatically once one is configured.
  `assets/geo/README.md` is the full guide, including how to convert a
  shapefile and how to simplify a large boundary.

Layers are fetched with `fetch()` when the map becomes visible. A missing or
malformed file logs a console warning and is skipped — it can never take the
map down.

Leaflet and the OpenStreetMap tiles are fetched from a CDN **only when the map
scrolls into view**, so a reader who never reaches that section downloads
nothing extra. If the CDN is unreachable the map hides itself and the country
list beside it — which carries the same information and is rendered
server-side — remains.

Set `settings.interactive: false` in that file to fall back to the lightweight
inline-SVG schematic, which needs no network at all.

There is no API key and no billing account, which is why this uses
OpenStreetMap rather than Google Maps.

The attribution is deliberately minimal — 9&nbsp;px, translucent, and the
"Leaflet" prefix removed. It cannot be removed entirely: the OpenStreetMap
licence requires credit. The full credit with a working link is repeated in the
caption underneath the map.

## Adding a new kind of page

Rarely needed, but if you want a seventh collection:

1. Add it under `collections:` in `_config.yml` with `output: true` and a
   permalink.
2. Add a `defaults:` entry pointing at a new layout.
3. Create `_layouts/<name>.html`, using an existing one as the model.
4. Create the folder `_<name>/` and a listing page at `<name>/index.html`.
5. Add it to `_data/navigation.yml` and to `search.html`'s `concat` chain.

## The content rule

**Nothing on this site may be invented.** If a fact is not in the project
material, the page shows a placeholder saying so. This is enforced by
convention, not by code, so it needs saying in review: a plausible-sounding
guess on a scientific platform is worse than a visible gap.

Current gaps are listed on the About page under "Known gaps in this site" —
keep that list current as material arrives.

## Relationship to version 1

An Astro implementation of the same site exists in `../site`. It is
feature-equivalent. This Jekyll version exists because it can be edited by

project. Prefer this one unless there is a specific reason not to.
